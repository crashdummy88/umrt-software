Peplink — Official Links

United Mobile RV is a Peplink Certified Associate. We supply and install mobile routers — from a single-WAN coach box to multi-SIM units — on fused DC, with Starlink and cellular as WANs when the job calls for it. Firmware and InControl come from Peplink only (Pepwave sits under the same support tree). Field work uses bonding and/or failover (SpeedFusion) — name the mode: Hot Failover ≠ Bonding ≠ Smoothing ≠ local outbound-only failover. Entry chassis may need PrimeCare or a feature pack before those modes unlock. Verify the SKU invoice. We do not market “bonding” when the coach only needs clean failover.

SpeedFusion honesty

  • Local outbound failover — no SpeedFusion peer; some sessions may drop on handoff.
  • Hot Failover — SpeedFusion/PepVPN peer; session-friendlier cutover when health checks fail.
  • Bonding — packet aggregation inside a SpeedFusion tunnel (peer + license/Care as required). Never promise 2× speed; Starlink + cellular latency mismatch can hurt interactive apps.
  • Smoothing — redundant copies across WANs; burns more metered data.

“Bonding not bonding” in the field is usually missing peer, missing Care/feature pack, or outbound-policy-only config — not a random firmware mirror.

Field notes (link shelf, not a how-to dump)

  • WAN Health Check flaps — fix power/RF and diversify targets before chasing firmware.
  • Starlink as WAN — official Ethernet adapter or Starlink router LAN → Peplink WAN; keep PoE brownout-aware (measure on site).
  • Cellular modem on the same chassis fused DC as the router — not a cigarette-lighter tap. Starlink PoE on its own fused path.
  • No invented watts / fuse / dBi matrices on this hub — quote after measurement.

Never

  • Cracked tools, unlocked firmware, or re-hosted vendor .bin / .swu.
  • Claiming bonding when only local failover is configured.
  • Inventing Starlink Certified / partner titles (Starlink = install capability only on the sales site).
