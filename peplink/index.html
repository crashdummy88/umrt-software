SpeedFusion honesty

  • Local outbound failover — no SpeedFusion peer; some sessions may drop on handoff.
  • Hot Failover — SpeedFusion/PepVPN peer; session-friendlier cutover when health checks fail.
  • Bonding — packet aggregation inside a SpeedFusion tunnel (peer + license/Care as required). Never promise 2× speed; Starlink + cellular latency mismatch can hurt interactive apps.
  • Smoothing — redundant copies across WANs; burns more metered data.

“Bonding not bonding” in the field is usually missing peer, missing Care/feature pack, or outbound-policy-only config — not a random firmware mirror.

Field notes (link shelf, not a how-to dump)

This page is the official firmware / InControl shelf. Install speak — fused DC, antenna placement, Starlink-as-WAN — lives on the sales-site connectivity page. We do not invent watts, fuse sizes, dBi tables, or prices here.

  • WAN Health Check flaps — fix power/RF and diversify targets before chasing firmware. A flapping WAN is usually brownout, bad SIM path, or one health-check target — not a random .bin.
  • Starlink as WAN — official Ethernet adapter or Starlink router LAN → Peplink WAN; keep PoE brownout-aware (measure on site). Bypass mode notes on /starlink/.
  • Cellular modem on the same chassis fused DC as the router — not a cigarette-lighter tap. Starlink PoE on its own fused path.
  • Name the SpeedFusion mode on the invoice and in InControl. “Bonding not bonding” is usually missing peer, missing Care/feature pack, or outbound-policy-only config.
